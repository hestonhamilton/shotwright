# Gallery viewer UX — plan (shotwright-746.40.2)

## Goal and bounds

Implement the settled owner decisions in `docs/shotwright-746.40.1-research.md` ("Owner decisions and redteam disposition"): a fitted, point-anchored screenshot viewer in gallery and compare, plus the specified count, empty-copy, and device-scale wording fixes. Keep generated pages self-contained and consumers thin. The research's earlier proposal that "Actual pixels" meant one intrinsic pixel per CSS pixel is superseded by its final disposition: **one intrinsic image pixel per viewing device pixel**. No recorded capture scale is needed.

This work does not change manifest schema or public package exports (`package.json:24-40`); it changes generated HTML, CSS, and inline JavaScript. Add one **minor** changeset in implementation: compare gains a new interactive viewer and gallery gains new entry and zoom actions, so this is a user-facing feature rather than a correction-only patch. The current package is `0.4.0` (`package.json:1-4`); a standalone release would request `0.5.0`, subject to other queued changesets. Do not add a dependency.

## Numbered implementation steps

The generated script binds each semantic `[data-viewer-open]` control to one `open(source, invoker)` function; source is the existing gallery `[data-original]` anchor (`src/gallery/render.ts:139-143`) or the existing compare `<img src="data:…">` (`src/gallery/render-compare.ts:14-22,65-67`). It reads that element's `href`/`src`, label, alt, and intrinsic dimensions; it never emits another base64 string into HTML. Give each compare source image a stable per-pair/per-side ID, including `Diff`, while streaming the same pair chunks (`src/gallery/render-compare.ts:135-151`). Missing or unreadable images have no opener (`src/gallery/render-compare.ts:14-17`). Keep downloads separate. **Tests:** `test/unit/gallery-render.test.ts:220-235,407-415` and `test/unit/gallery-compare-render.test.ts:13-22,125-145` assert one data URI per source, shared viewer markup/script, escaped labels, A/B/Diff identities, and no opener for absent images. 3. **Implement fitted default, true device-pixel mode, and anchored toggling in the shared viewer.** Replace the fixed `height: calc(100% - 65px)` (`src/gallery/assets.ts:142-150`) with a bounded dialog flex or grid column: a wrapping header takes its natural height, the image surface is the remaining `minmax(0,1fr)` area and scrolls. Set title to `{shot name} — Screenshot` (current text is in `src/gallery/render.ts:488` and `src/gallery/assets.ts:314`). On `showModal`, after layout measurement, compute `cssActualW = intrinsicW / window.devicePixelRatio`, `cssActualH = intrinsicH / window.devicePixelRatio`, and `fit = min(surface.clientWidth/cssActualW, surface.clientHeight/cssActualH, 1)`; set image CSS dimensions to `fit × cssActual` in fit mode and `cssActual` in actual mode. Recompute on viewport resize and DPR changes; closing removes the viewer image node, as current close does (`src/gallery/assets.ts:327-335`). Use a button whose **label changes** between `Actual pixels` and `Fit to window`, since each label states the next action; omit `aria-pressed` to avoid a second, potentially conflicting state channel. Explain in nearby help text that actual means one image pixel per viewing device pixel. Clicking the viewer image toggles with `zoom-in`/`zoom-out` cursor: derive the clicked intrinsic image fraction from its pre-toggle rectangle, set the new size, then set surface `scrollLeft`/`scrollTop` so that point remains at the clicked surface coordinates, clamped by browser scroll bounds. A dedicated button toggles around the surface center. Refit after resize; in actual mode recompute CSS dimensions for the new DPR and preserve the normalized image point at the surface center, with scroll clamped. The image's click handler must not fire from a dialog control. Keep native Escape close and the queued-close focus guard (`src/gallery/assets.ts:327-335`), especially the existing same-task regression (`test/unit/gallery-browser.test.ts:344-373`). **Tests:** add a genuinely large 1280×8000 PNG and a DSF=2 capture in `test/unit/gallery-browser.test.ts`; generate them with Playwright screenshot capture or a row-streaming PNG writer, because the existing `uniquePng` helper accumulates every pixel in a JavaScript array (`test/unit/gallery-browser.test.ts:39-57`). Run Playwright viewing contexts with `deviceScaleFactor: 1` and `2`. Assert fit contains the entire tall image within the measured surface without upscaling, actual CSS dimensions equal intrinsic/DPR, image click keeps the chosen image point under the cursor within rounding/scroll clamping, button returns to fit, resize recomputes, long wrapped titles do not overlap the surface, Escape restores each invoker, and same-task close/refocus still wins. ## Redteam disposition (2026-10-28)

A fresh delegate redteamed this plan. The amendments below bind the implementation and override the steps above where they conflict.

- **No-JS truthfulness — accepted.** Preview openers in the gallery and in compare render in HTML as `<button type="button" disabled>`. The viewer script removes `disabled` when it binds them, so without JavaScript nothing promises an action it cannot perform. The gallery's "View full screenshot" text button follows the same rule. Download links stay usable and unchanged. The no-JS browser tests assert this state.
- **Deterministic synchronization — accepted.** The viewer sets `data-viewer-state="ready"` on the dialog once the image has decoded (`await img.decode()`), its size has been applied, and one `requestAnimationFrame` has passed. It resets the attribute on close, on toggle start and on resize. Geometry assertions wait for that attribute, or use `page.waitForFunction` on measured geometry. They never use fixed sleeps. The same-task close/refocus regression test (`test/unit/gallery-browser.test.ts:344-373`) is preserved unchanged.
- **Click anchor definition — accepted.** The anchor is the clicked point as a fraction of the image's rendered `getBoundingClientRect()`, which handles fitted images centred inside a larger surface. After the toggle, the surface scrolls so that fraction sits under the click's surface coordinates, clamped to the scroll bounds. Tests assert exact anchoring (within ±1 CSS px) where scrolling allows it, and assert the clamped scroll value at an edge separately.
- **Streamed/direct equality — accepted.** Equality is asserted only for unchanged, readable inputs. A separate test covers a PNG that fails to read late, during pair hydration (`src/gallery/generate-compare.ts:296-338`): it asserts truthful verdict counts and no opener for the unreadable side.
- **Serve scope — noted.** `shotwright serve` does not serve compare pages (`src/gallery/server.ts:147`) and sends no CSP header (`src/gallery/server.ts:10,318`). The compare page's meta CSP is the operative policy when the file is opened directly. No server change belongs in this epic.
- **Hash vs `'unsafe-inline'` — declined for this epic.** Compare follows the gallery's existing mechanism, as the research disposition decided. Tightening both pages to a script hash is a candidate follow-up, not a defect.
- **Large-image test isolation — accepted.** One deterministic tall PNG is generated once per test file, outside the 60-shot loop, and reused across the DPR 1 and DPR 2 contexts.
