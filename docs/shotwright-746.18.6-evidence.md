## 0. How to use this document

This pack is a snapshot with a date on it. `scripts/flip-evidence.sh` is what makes
it checkable rather than merely trusted.

```sh
scripts/flip-evidence.sh
```

It prints an **evidence digest** over its findings. If that digest still reads
`e6c35bc42cfcf207`, the finding set adjudicated below is unchanged and this
document still describes reality. If it differs, something moved — re-read rather
than re-trust.

The digest is **stable under committing this document**, which is not obvious and
was checked rather than assumed: every value quoted below was already in the
adjudicated set, so the pack adds no new distinct finding. That is also why the
fake credentials in §1 are described rather than reproduced — quoting those *would*
have changed it, and would have made this file a source of leak-gate findings.

**Run it immediately before flipping, not once at the start of the session.** The
control that keeps the board ref deleted is machine-local and does not survive a
fresh clone (§5), so a check from an hour ago proves less than it appears to.

### What the script never contains

The operator's username, the self-hosted forge hostname, and the backup
destination are all **derived at runtime** — from `$HOME`/`$USER`, from `git
remote -v`, and from the installed systemd unit respectively. None is written into
the script, because committing any of them would be the exact disclosure the sweep
exists to detect. The script is therefore correct on any machine and discloses
nothing on all of them.

### The script has been shown to fail

A check only ever observed passing has not been shown to work. Demonstrated
2026-09-03 in a throwaway clone with its remote repointed at a dead path:

| Case | Result |
|---|---|
| Operator username seeded into a committed file | `FAIL … (tree:1 history:1)`, exit 1 |
| Same file then `git rm`'d and committed | **still** `FAIL … (tree:0 history:2)`, exit 1 |

The second row is the one worth internalising: deleting the file cleaned the tree
and left history untouched. For a repo about to become public that distinction is
the whole game, and the check gets it right.

**And it has been caught failing the other way.** Redteam 2 (2026-10-05) ran the
script in a sandbox where `/dev/stdout` was not writable; gitleaks exited 1 on the
three fixtures, the report capture was empty, and the script printed
"0 finding(s)" and a different digest. The exit status was never read. It now is:
the report goes to `--report-path -`, exit 0 means clean, exit 1 must come with a
captured report, and anything else fails closed as "NOT RUN". Two more clone-only
hazards from the same run are closed: the backup check names the database by
package name rather than directory name, and a checkout with no forge remote
*records* that the hostname check did not run (which changes the digest) instead
of silently passing.

## 1. Full-history secret scan

`gitleaks 8.30.1`, **3 commits scanned** (89 at first assembly on 2026-09-03; 96 at the 2026-10-05 re-run after PR #53; 109 on the first recreation after PR #69; 1 after the second recreation squashed main to a single commit; 3 after PRs #1 and #2 on the recreated repository — the same three findings every time) — the count is taken from gitleaks' own
output, not from `git rev-list --all --count`, which answers a different question
and would overstate coverage by roughly fifty commits while looking like a
measurement.

**The scan runs over a `--no-checkout` clone of the same history, not the
working tree.** gitleaks reads a `.gitleaksignore` from the root of whatever
repository it is pointed at, and in `git` mode it does so whatever
`--gitleaks-ignore-path` says (measured on 8.30.1, `shotwright-746.18.32`
follow-up). The repository carries one, for these three fixtures, so that
third-party scanners stay quiet after the flip — and the moment it landed, this
script reported 0 findings and a different digest. A clone with no working tree
has the identical commits and no file for the scanner to read suppressions
from, so the three findings below are reported raw and adjudicated **here**,
by a reader, never by a line in the tree. The same reasoning is why the tarball
gate scans an extracted archive.

**3 findings. All benign, all in one file, all deliberate.**

| Fingerprint | Rule |
|---|---|
| `7af1f06…:scripts/dolt-ref-inspect-selftest.sh:generic-api-key:108` | generic API key |
| `7af1f06…:scripts/dolt-ref-inspect-selftest.sh:aws-access-token:109` | AWS access key |
| `7af1f06…:scripts/dolt-ref-inspect-selftest.sh:aws-access-token:125` | AWS access key |

All three are synthetic seeds in the self-test that proves the dolt-ref classifier
fires: a GitHub token of ascending hex, an AWS key id that is literally the
alphabet, and a connection string whose password is `hunter2` on an
`example.invalid` host. **The literals are deliberately not reproduced here** —
writing them into this document would make the evidence pack itself a source of
three more gitleaks findings, and would put credential-shaped strings in a file
that is about to be public. Read them at
`scripts/dolt-ref-inspect-selftest.sh:105-112` if you want to confirm the
adjudication. They are textbook-fake by construction: a self-test that proves a credential detector works has to contain
things shaped like credentials, and the alternative — a detector never
demonstrated firing — is worse.

**No real credential was found anywhere in history.**

## 2. The identifiers that must not appear

These are binary. Unlike §3 there is no benign match: the operator's real username
and the private forge hostname have no legitimate reason to be in a committed file
or in history.

| Check | Tree | History | Result |
|---|---|---|---|
| Operator username | 0 | 0 | **absent** |
| Self-hosted forge hostname | 0 | 0 | **absent** |
| `github.com` | present | present | **expected** — it is `package.json`'s repository URL |

The forge hostname lives only in `local/forge-ci.md` (gitignored) and in `git
remote -v` (not a file). This matters because `shotwright-746.18.3` measured that
the leak gate does **not** catch a self-hosted forge hostname — it is not a host
path, a LAN IP, or a username. That gap is real; this check is what covers it, and
only for hostnames the runtime environment knows about.

## 4. Board ref disposition

```
git ls-remote origin | grep dolt   →   (no output)
```

`refs/dolt/data` and the `__dolt_remote_info__` branch are **absent from the
remote**, verified by looking, re-checked 2026-09-03 after all merges landed and again on 2026-10-05 after PR #53.

**This is not a one-time gate.** The control that keeps it deleted is bd's dolt
remote origin pointing at a local `file://` path, which lives in `repo_state.json`
under the shared server's data dir — *not* in the repo. On any new machine or fresh
clone, bd re-derives origin from the git remote and the next `bd dolt push`
re-creates the ref. There is no tracked equivalent; `sync.remote` in
`.beads/config.yaml` is **not** the key `bd dolt push` reads. Measured in
`shotwright-2sr.4`, along with three other controls that do not work.

Re-run the check immediately before flipping, and after any `bd dolt remote`
operation.

## 6. The residual the owner must re-affirm

**Read this at the moment of flipping, not once in the abstract.**

Deleting `refs/dolt/data` removed **discoverability, not the objects**. GitHub
retains unreachable objects, and they remain reachable by SHA to anyone who knows
or guesses one. The board's contents are therefore not *destroyed* on GitHub's
servers — they are unadvertised.

The owner accepted this knowingly (decision 3, 2026-08-02) and instructed that it
not be re-litigated. It is restated here so the acceptance is re-affirmed at the
moment it takes effect rather than inherited from a prior session.

## 7. What this pack does NOT establish

Stated as gaps rather than rounded up.

1. **Other repositories on the account are out of scope and decided per
   repository (`shotwright-uke`).** No repo carrying `refs/dolt/data` may be made
   public until its own ref is dispositioned. Nothing here covers them.
2. **Dependabot's reactive half has never run.** Do not record the flip as
   "switching Dependabot on" — *version* updates already run on this private repo
   (a github-actions bump PR landed 2026-08-02). The flip enables **alerts and
   security updates** only.
3. **The required status check named `verify` is not enforced.** Rulesets return
   403 `Upgrade to GitHub Pro or make this repository public` while the repository is
   private. It becomes enableable *at* the flip; the check name is lowercase and
   string-exact.
4. **Hostname detection is incomplete by construction.** A LAN service reached at a
   public DNS name is indistinguishable from any other domain without knowing which
   names are the operator's.
5. **Candid internal prose, third-party names and non-path PII were READ, not
   just scanned — on 2026-10-05, after this pack was first written.** The read
   produced 131 flags across 49 files; the owner chose to resolve all of them,
   and PR #66 did (`shotwright-746.18.24`): sibling projects named by role, the
   other repositories in the 2sr.3 audit reduced to an out-of-scope statement, ADR
   0015's endpoint details removed and the ADR marked superseded, host roles,
   service versions and billing state gone, delegated-agent provenance made
   neutral, the orchestrator skill removed from the tree. Accepted and left as
   is, with reasons: the four commit author identities (owner-accepted,
   `2sr.1-research`); the word "Codex" where it names the `codex-jobs` tooling
   itself; "private, headed public" wording, which the flip corrects. The
   mockup HTML files were grepped for the same identifier list and are clean.
   This script's digest did not change, because the sweep it digests covers
   identifiers, not prose.
6. **`local/` was not audited** — it is gitignored and does not ship, but it has
   never been confirmed to be free of anything that got there by accident.

7. **The pre-scrub text was in git history. The repository was recreated
   from rewritten history, that proved insufficient, and it is recreated again
   from a single commit** (ADR 0020 and its amendment, beads
   `shotwright-746.18.6.1` and `shotwright-746.18.31`, both 2026-10-05). The
   first recreation replaced a list of strings throughout history; an audit the
   same evening showed every pre-scrub file version still reachable with the
   strings swapped out, the scrub commit's message describing what it removed,
   the workstation's own LAN address committed as a test fixture and listed in
   §3 as invented, and a personal e-mail address in most commit headers. The
   second recreation pushed one commit (`7af1f06`), authored under the GitHub
   noreply identity, whose tree is the fixed tree. Check **3b** proves the clone holds
   none of the superseded commits and that every commit identity is a noreply
   one; the machine-address check in §3 proves the fixture is gone. Two
   consequences remain: pull-request numbers and commit hashes cited in ADRs
   and in this pack refer to private history, and any clone taken before the
   second recreation must never be pushed from, which 3b refuses.

## 8. Flip checklist

1. `scripts/flip-evidence.sh` → exit 0, check 3b passes, digest matches `e6c35bc42cfcf207`.
2. `git ls-remote origin | grep dolt` → no output. (§4 — the control is machine-local.)
3. Re-read §6 and re-affirm the SHA-reachability residual.
4. Accept §7 as the list of what is *not* covered, item 5 especially.
5. **Owner** changes repository visibility, by hand, in the GitHub UI.
6. Immediately after: enable the required status check named exactly `verify`
   (lowercase, string-exact), now that rulesets are available.
7. Confirm Dependabot **alerts and security updates** are active — the narrow claim
   from §7.2, not the broad one.
8. Check that GitHub detected the license: the repository header should read
   "AGPL-3.0". `LICENSE` carries a 17-line copyright notice above the verbatim
   text, and some detectors (licensee) mis-classify a file with a preamble. If
   it shows "Other" or nothing, move the notice into `NOTICE` (or README) and
   leave `LICENSE` as the verbatim text — the `expected-files.txt` allowlist
   must then admit `NOTICE`, which npm ships unconditionally.
9. Record the flip date and this pack's path on `shotwright-746.18.6`, then close it.
