# shotwright-746.62 — selectable CI artifact upload plan

- **Phase:** P
- **Decision:** Follow the accepted policy in `docs/adr/0026-ci-artifact-upload-policy.md:18-27` and the final owner decision in `docs/shotwright-746.62-research.md` ("Redteam and owner decision").

## Goal

Let callers choose `always`, `on-failure`, or `never` for the existing whole-run GitHub artifact. Preserve the reusable workflow's `always` and seven-day defaults; make the generated caller use `on-failure` and two days on `pull_request`, and `always` and seven days on `workflow_dispatch` (`.github/workflows/shotwright.yml:34-41,194-202`; `templates/github/shotwright.yml:3-5,17-24`; `docs/adr/0026-ci-artifact-upload-policy.md:18-27`). A selected upload never changes the shot verdict or adds an image-difference gate (`docs/design.md:34-36`; `docs/adr/0026-ci-artifact-upload-policy.md:18-27`).

**Premise check:** The bead's description still matches the code: there is no `upload` input among `.github/workflows/shotwright.yml:5-41`, and the upload currently runs whenever a directory resolves, with a seven-day default (`.github/workflows/shotwright.yml:34-37,194-202`).

## Risks and rollback

- GitHub may treat post-failure `if:` expressions, step outcomes, or cancellation differently from static inspection. The pushed truth table above pins the semantics before sign-off. If it fails, fix in I and repeat the affected V run.
- A shot can fail before writing its invocation directory; the resolver will report its existing error for `always` or `on-failure` when `shot` itself fails, and no artifact can be uploaded (`.github/workflows/shotwright.yml:179-193`). The summary only claims an artifact after upload returns a URL (`.github/workflows/shotwright.yml:203-209`).
- Revert the optional input and event expressions to restore the old always-upload behavior. Restore the prior template or pin an earlier release to reverse caller defaults (`templates/github/shotwright.yml:17-24`; `docs/adr/0026-ci-artifact-upload-policy.md:18-27`). No stored run format or runtime API changes.

## Considered and declined

- Changing the reusable default to `on-failure` or two days: violates the owner decision and silently changes existing callers on tag upgrade (`docs/adr/0026-ci-artifact-upload-policy.md:18-27,29-38`).
- `failure()` alone: it includes setup failures and does not express the shot-step contract (`.github/workflows/shotwright.yml:67-136,137-178`; `docs/adr/0026-ci-artifact-upload-policy.md:23-26`).
- Production direct `archive: false` gallery, split gallery/media artifacts, and off-GitHub storage: duplicate or expand storage and need independent browser and cost evidence (`docs/shotwright-746.62-research.md`, "Redteam and owner decision"; `docs/adr/0025-off-github-run-storage-is-an-opt-in-s3-compatible-publish.md:18-45`).
- Changing the demo's every-push trigger here: the trigger is currently `push` (`.github/workflows/demo-shots.yml:3-4`); bead 746.63 owns that policy (`docs/shotwright-746.62-research.md`, "Redteam and owner decision").
