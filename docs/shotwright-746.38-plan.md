## Goal and binding decisions

Implement the verdicts in [E12 research](shotwright-746.38-research.md), including its redteam revision and the owner's C5 decision. The [consumer brief](shotwright-746.38-consumer-brief.md) supplies the six repros. This plan does not reopen those decisions. The chosen compatibility boundary is one 0.4.0 minor release, assembled with one changeset.

- **C1:** Document how to carry a project `grep`/`grepInvert` into the shots config; refuse explicit `projects` plus harness top-level `viewport` or `deviceScaleFactor` after the config-probe return. Preserve per-project `use`.
- **C2:** Run `check` before `--only` selection. A failed check fails the test; an omitted shot has no PNG or sidecar. Document prior-shot file dependencies.
- **C3–C4:** Keep `artifact()` returning `Promise<void>`. Document Playwright per-test scratch paths; stream path sources into the existing exclusive destination claim, with inode-aware failure cleanup.
- **C5:** Set `engines.node` to `>=22.12.0`, retain ESM-only exports, and explain the dropped runtimes and `require(esm)` qualification.
- **C6:** Add optional descriptive `note` to shot sidecars and v2 entries, card display, and search. Preserve `(spec,name)` pairing and manifest version. View the changed gallery before shipping.

**Wrong premise in epic acceptance:** “npm refuses to install” cannot be guaranteed by a dependency's `engines.node` alone. npm treats `engines` as advisory unless the consumer enables `engine-strict`; its default is false ([npm package metadata](https://docs.npmjs.com/cli/v11/configuring-npm/package-json/#engines), [npm config](https://docs.npmjs.com/cli/v11/using-npm/config/#engine-strict), read 2026-10-27). The binding C5 research verdict is the accurate metadata floor. W4 verifies both the default warning and strict-mode refusal, and the release notes state this limit. No install-time script or separate dependency is introduced to force refusal.

### W2 — scratch workflow and bounded artifact copy (C3/C4)

**Files:** `src/capture.ts:71-97,239-290`, `test/unit/capture.test.ts`, `test/smoke/contract-consumer.test.ts`, `README.md:99-111`, and, if the template's consumer guidance covers artifacts, `templates/skills/shots-harness/SKILL.md`. No new public scratch API or return value. W2 supplies the C3/C4 changeset paragraphs to W4.

1. Document `const source = test.info().outputPath('report.pdf')`: generate at `source`, inspect that same path with an external tool, then call `await artifact('report.pdf', { path: source, contentType: 'application/pdf' })`. The caller already knows the scratch source. The reporter removes the run's `.pw` staging directory on ordinary pass **and fail** exit (`src/index.ts:102-105`, `src/reporter.ts:210-219`), so inspection and publication occur before test completion; hard termination has no cleanup promise. Playwright documents `outputPath()` as a unique per-test output path ([TestInfo](https://playwright.dev/docs/api/class-testinfo#test-info-output-path), read 2026-10-27).
2. Preserve `openWrite`'s exclusive/no-follow flags and parent checks (`src/capture.ts:71-97`) and existing duplicate/retry authorization (`src/capture.ts:261-274`). For a `path` source, replace the whole-file `readFileSync` (`src/capture.ts:254-259`) with `fs.createReadStream(source)`. Await its `open` event (reject its `error` event), and verify the opened source is a regular file with `fstat` **before** the retry-replacement `unlinkSync(dest)` at `src/capture.ts:261-274`. If source opening or verification fails, destroy the reader and leave the prior attempt's artifact intact. After retry authorization, claim the destination once through `openWrite`. Iterate `for await (const chunk of reader)` and write each chunk through that claimed fd using `fs.writeSync(fd, chunk, offset, remaining)` in a loop until all bytes are written; reject a zero-byte write and handle every short write. Count successful `bytesWritten` values; only a completed copy gets a sidecar with that exact count. Record the claimed `(dev,ino)` immediately after `openWrite`; on failure remove `dest` only if `lstatSync(dest)` still identifies the claimed regular inode. Put reader destruction and the destination fd's **single** `closeSync` in one `finally`, including error paths; the reader never owns the destination fd. Preserve the `body` Buffer/string branch and its byte count. Node documents [read streams and async iteration](https://nodejs.org/api/fs.html#fscreatereadstreampath-options) and [`fs.writeSync`'s returned byte count](https://nodejs.org/api/fs.html#fswritesyncfd-buffer-offset-length-position) (read 2026-10-27). This provides bounded copy memory relative to file size, not an atomic whole-file destination; the sidecar marks a completed copy. On a retry mid-copy failure, the old bytes have already been unlinked: remove the claimed partial inode, write no sidecar, and fail the test. Do not claim that this restores the previous attempt.

**Installed-Node probe (2026-10-27):** A throwaway script under `local/` exercised this source-open-first, async-chunk-read, `writeSync`-loop and single-destination-close design on Node v24.16.0; it was deleted afterward. A missing source returned `ENOENT` and preserved the previous artifact. Destroying the reader after the first chunk returned the injected mid-read error, removed the claimed destination, and did not mask it with `EBADF`. A normal 26-byte copy used seven chunks, matched the source exactly, and left the destination fd closed. This pins the design on the installed Node; the unit tests below cover the implementation and supported runtimes.

**Pins/tests:** Extend `test/unit/capture.test.ts` for multi-chunk source identity and exact byte count, zero-byte source, missing source on an initial attempt and on a retry (the prior bytes and sidecar remain), injected read failure after one chunk on a retry (the old bytes are gone, claimed partial inode is removed, no new sidecar, test fails), injected destination short writes and failure, no sidecar on failure, no leaked destination fd, cleanup of the claimed inode, and preservation of a replacement inode at the same pathname. Confirm the body branch still writes identical bytes. Extend `test/smoke/contract-consumer.test.ts` with `test.info().outputPath()` → external-reader step → `artifact({path})` on an ordinary failed run, and verify `.pw` cleanup after the reporter exits. A large sparse or generated source test must establish that `readFileSync(source)` is not called and copy succeeds in chunks; do not claim a measured peak-memory reduction without a benchmark.
