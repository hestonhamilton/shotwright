# E11 consumer follow-up — research

**Bead:** `shotwright-746.32.2` · **Epic:** `shotwright-746.32` · **Phase:** Research · **Date:** 2026-10-26

## Context and boundaries

The [anonymized consumer brief](shotwright-746.32-consumer-brief.md) reports observations on 0.2.0. Its counts and cross-distribution pixel examples are consumer reports, not measurements repeated here. This worktree's code is the grounding below. D1, D2 and N3 belong to `shotwright-746.32.1`; this research makes no recommendation for them. The owner already supplied the research constraints and scope in the bead request; no kickoff preference is needed to determine the technical options.

The design requires review artifacts and an opt-in parity gate (`docs/design.md:84-87`, `docs/design.md:110-116`), byte-preserving capture (`src/capture.ts:83-105`), an atomic manifest and last-passed `latest` (`src/runs.ts:113-130`, `src/reporter.ts:167-180`), a self-contained gallery (`src/gallery/render.ts:408-445`), and the consumer's Playwright CLI (`src/cli.ts:436-453`, `src/cli.ts:623-640`). Any change must preserve these.

### A3 experiment: Playwright 1.64.0

Used a temporary `local/` Playwright 1.64.0 install, a `.shots.ts` file importing a helper that registers `test()`, and a custom reporter. Ran `node local/a3-probe/node_modules/@playwright/test/cli.js test -c local/a3-probe/config.ts` (and a nested spec). Both tests passed. The observed paths below are reduced to testDir-relative form; no host path is needed to state the result.

| Value | Root spec | Nested spec |
|---|---|---|
| `test.info().file` | `helper.ts` | `nested/helper.ts` |
| `test.info().titlePath[0]` | `table.shots.ts` | `nested/table.shots.ts` |
| reporter `test.location.file` | `helper.ts` | `nested/helper.ts` |
| reporter file suite `location.file` | `table.shots.ts` | `nested/table.shots.ts` |

Reporter `test.titlePath()` began with two empty/root/project slots before the file and test titles in this probe; do not index it like `TestInfo.titlePath`. Resolve the ancestor whose suite type is `file` (`Suite` documents the hierarchy); validate the resulting spec against testDir. The experiment also confirms the helper location remains useful as a declaration location, but it is the wrong canonical capture identity. Source consumers of each value are `src/capture.ts:76-79`, `src/capture.ts:126-128` and `src/reporter.ts:60-80`.

For D4, a temporary config whose top level threw the same guard message was loaded with Playwright 1.64.0's `test -c` command. It exited 1 and printed the message followed by a multi-frame stack through Playwright's `requireOrImport`, `loadUserConfig`, and `runTests`. The repo guard is at `src/index.ts:49-50`; no application code or output directory was touched in this probe.

Redteam follow-up probe under `local/e11-d4-probe/`: with Playwright 1.64.0, a config that called `console.error` then `process.exit(1)` printed one stderr line and exited 1; an equivalent top-level throw printed 16 stderr lines and exited 1. The probe used `test -c ... --list` and did not execute tests. It confirms the cosmetic gain, while the config-import process exit remains an unacceptable integration cost for a reusable library.

A second `local/e11-d4-probe/` probe used a config with `retries: 0`, a reporter that printed the effective project setting, and `playwright test --retries=2`. The reporter printed `effective-retries=2`; no browser was needed. This confirms CLI retries can reach the harness despite its config default (`src/index.ts:67-73`; `src/cli.ts:637-640`).

### B1 failure-publication invariant

The collision namespace remains `(spec,name)`, including across projects (`docs/adr/0021-shot-identity-and-manifest-v2.md:12-28`). Reserve the final path atomically **before capture**, then stage with explicit PNG type and link the captured bytes unchanged under that reservation; the current direct screenshot path can overwrite (`src/capture.ts:79-105`). Atomicity matters for simultaneous workers from parallel projects or caller-enabled `fullyParallel` (`src/index.ts:67-80`). The harness sets retries zero, yet forwards passthrough CLI arguments (`src/index.ts:67-73`; `src/cli.ts:637-640`); The local probe below confirmed that `--retries=2` yields effective retries 2; P must pin final-attempt sidecar behavior before designing retry replacement. No retry replacement is recommended now. A duplicate should fail its test and allow failed-run publication (`src/reporter.ts:70-83`, `:135-180`). A late duplicate sidecar from an older writer is the recovery case: retain only unambiguous captures, record the diagnostic, set effective status `failed`, and block `latest`. P pins: sequential duplicate, parallel workers, two projects, CLI retry override, late duplicate with Playwright-passed result, byte identity, reservation cleanup/crash behavior, and manifest/`latest` status.

### A4 provenance collection details

Proposed shape: run-level `environment: {platform, distribution: {id, versionId}|null}` and capture-linked browser observations `{name, version}`. On Linux parse `ID` and `VERSION_ID` from os-release; use actual `browser.version()` from the running browser, not the reporter's Playwright version (`src/reporter.ts:33-36`). P must pin how each shot maps to its effective browser when a project uses multiple configurations (`src/index.ts:80-100`). Missing old-run or collection fields mean “provenance unavailable”; unequal known fields mean “known fields differ.” Equal fields yield no equivalence claim. The advisory changes neither verdict nor gate (`src/gallery/generate-compare.ts:125-130`). No executable path or identity, kernel release, or font digest in this first banner. A future font digest needs tested normalization and byte semantics: path-sensitive descriptors can differ on equivalent fonts, while the same descriptors can mask changed bytes.

## Prior art and currency

All links below were read **2026-10-26**. These are upstream contracts or release notes, while the A3/D4 observations above are local experiments.

- Playwright [TestInfo](https://playwright.dev/docs/api/class-testinfo) documents `file` as declaration source and `titlePath` as starting with test file name. [TestCase](https://playwright.dev/docs/api/class-testcase) documents reporter location and parent; [Suite](https://playwright.dev/docs/api/class-suite) documents root → project → file hierarchy, file-suite title/location, and suite type. Read 2026-10-26.
- Playwright [test project grep](https://playwright.dev/docs/api/class-testproject) states `-g` matches a joined string of project, file, describe, test and tags; this supports N3's split-off documentation fix and explains why an anchored test title at the beginning fails. Read 2026-10-26.
- Playwright [Browser.version](https://playwright.dev/docs/api/class-browser) and [test use options](https://playwright.dev/docs/test-use-options) document the running browser version and browser configuration used in A4's proposal. Read 2026-10-26.
- Node [OS API](https://nodejs.org/download/release/v22.18.0/docs/api/os.html) provides platform; the [freedesktop os-release specification](https://www.freedesktop.org/software/systemd/man/262/os-release.html) identifies `ID` and `VERSION_ID` as Linux distribution identifiers. Read 2026-10-26.
- Node [20.19.0 release](https://nodejs.org/en/blog/release/v20.19.0) and [22.12.0 release](https://nodejs.org/en/blog/release/v22.12.0) state when `require(esm)` became enabled by default; both describe the synchronous-module limit and `module-sync` condition. Read 2026-10-26.
- npm [package.json](https://docs.npmjs.com/cli/configuring-npm/package-json/) documents `engines` as advisory unless `engine-strict` is set, and `exports` as conditional entry routing. A `require` condition alone cannot transpile ESM; that conclusion follows from Node's require rules and this package's ESM target (`package.json:5`, `package.json:24-37`). Read 2026-10-26.
