# E12 consumer follow-up — research

**Bead:** `shotwright-746.38.1` · **Epic:** `shotwright-746.38` · **Phase:** R · **Date:** 2026-10-27

## Context and boundaries

The [anonymized consumer brief](shotwright-746.38-consumer-brief.md) describes 0.3.0 use. This research tests its hypotheses against the current worktree and external primary sources. It recommends behavior; it does not change implementation, tests, templates, package metadata, or README. The owner chose a config error on mixed `projects` and top-level viewport settings and chose `engines.node: >=22.12.0` for 0.4.0. The owner's second decision request is settled by the C2 verdict: a failed `check` should fail the test even when the shot is filtered.

The binding local constraints are the Playwright runner and peer dependency ([ADR 0001](adr/0001-package-on-test-runner.md), [ADR 0002](adr/0002-playwright-peer-dependency.md)); review artifacts with an opt-in compare gate (`docs/design.md:30-36`, [ADR 0024](adr/0024-review-based-baselines-declined.md)); and manifest v2's `(spec,name)` identity and path checks ([ADR 0021](adr/0021-shot-identity-and-manifest-v2.md)). Notes must remain descriptive metadata, not new comparison keys or baseline verdicts.

## C1 — production filter and project device options

**Code and ask.** `ShotsConfigOptions` accepts Playwright config keys, plus harness `viewport` and `deviceScaleFactor` (`src/index.ts:24-31`). The factory spreads `opts` into the config (`src/index.ts:67-69`), then creates a default `shots` project without a project-level grep (`src/index.ts:80-100`). Thus top-level `grep` and `grepInvert` survive. The consumer passed only `base.use`, omitting the base config's project (`C1` in the brief); project `grep` cannot cross that omitted boundary. With explicit `projects`, the factory maps each project's `use` to enforce capture toggles, while `opts.viewport` and `opts.deviceScaleFactor` are read only in the default-project branch (`src/index.ts:80-99`). The README's example supplies both project and top-level viewport values (`README.md:243-254`), reinforcing the ambiguity.

**Prior art and alternatives.** Playwright says top-level project options are shared by projects and documents both `testConfig.grep` and `testProject.grep`; its CLI has separate `--grep`/`--grep-invert` filters ([TestProject](https://playwright.dev/docs/api/class-testproject), [CLI](https://playwright.dev/docs/test-cli), read 2026-10-27). Nx's Playwright preset is spread into `defineConfig`; overrides after the spread are explicit, and browser device values live under each project `use` ([Nx Playwright](https://nx.dev/docs/technologies/test-tools/playwright/introduction), read 2026-10-27). This supports pass-through of projects and clear precedence, not guessing that a consumer's separate base config exists. Playwright's top-level `use` shares options across projects ([TestConfig](https://playwright.dev/docs/api/class-testconfig), read 2026-10-27). Applying the harness viewport/scale to every passed project would erase intentional mobile or per-project device values unless an override order is chosen; applying only when absent would create a second implicit inheritance rule. Vite's empty-`envPrefix` error addresses secret exposure, a different risk, so it is weak precedent for this device-setting choice ([Vite shared options](https://vite.dev/config/shared-options), read 2026-10-27).

**Local experiment.** After compiling the worktree, a temporary three-test spec contained a safe tag, a blocked tag, and a test with both. `playwright test --list` found 3 with no filter; 2 with top-level `grep: /@prod-safe/`; 1 with top-level `grepInvert: /@blocked/`; and 1 with both. `--grep unsafe` with the top-level safe filter found 0, and with a project-level safe filter also found 0: CLI grep narrowed rather than bypassed the config gate. `--grep safe` matched both safe-tagged tests because it also matched the substring in `@prod-safe`; use a precise expression when testing title selection. This was Playwright from this worktree's installed dependencies, no browser launch. The temporary files were removed.

**Verdict — ship differently.** Document that `use: base.use` transfers only `use`; pass `projects: base.projects` for a project gate, or set a deliberate top-level `grep`/`grepInvert` on the shots config. Do not add duplicate grep options or silently copy a project filter. Reject `projects` together with the harness top-level `viewport` or `deviceScaleFactor`, naming the conflicting fields and directing values to each `project.use`. Place this validation **after** the config-probe return (`src/index.ts:33-48`). `runs`, `compare`, and `gallery` all probe for the output directory before reading existing runs (`src/cli.ts:550-606`, `src/cli.ts:715-725`, `src/cli.ts:775-790`, `src/cli.ts:803-830`); the refusal must not block access to those runs. With explicit projects, preserve each project's `use` values (`src/index.ts:80-87`). The plan must fix the README example that currently shows the refused combination (`README.md:243-254`) and add a migration note. A warning is too weak because shotwright runs unattended in CI, where it can go unread while captures use the wrong device settings. Refusal is limited to capture configuration; read-only run access remains available.

## C2 — filtered shot checks

**Code and ask.** `shot()` validates the run environment and name, then returns on an unmatched `SHOTWRIGHT_ONLY` before obtaining test info or calling `opts.check` (`src/capture.ts:155-171`). `parseOnly` and `shouldCapture` implement substring filtering (`src/filter.ts:5-15`). Only captured shots write sidecars with `checked: opts.check !== undefined` (`src/capture.ts:200-214`); the manifest has no record for an omitted shot (`src/manifest.ts:14-28`, `src/manifest.ts:74-91`). The README promises that `--only` filters writes rather than execution (`README.md:174-178`), and says `checked` records callback completion, not assertion truth (`README.md:100-107`). The consumer wants checks to run or the skip disclosed.

**Prior art and alternatives.** Playwright's `--update-snapshots` changes when snapshot files are written, while screenshot expectations remain assertions; failed assertions fail tests by default ([snapshot modes](https://playwright.dev/docs/api/class-testconfig), [assertions](https://playwright.dev/docs/test-assertions), read 2026-10-27). Storybook's test-runner distinguishes `exclude` (test not selected) from `skip` (explicitly flagged skipped) rather than silently reporting a passing test whose check did not run ([Storybook test-runner](https://storybook.js.org/docs/11/writing-tests/integrations/test-runner), read 2026-10-27). BackstopJS `--filter` selects whole scenarios, including their scripts and captures ([BackstopJS README](https://github.com/garris/BackstopJS/blob/master/README.md), read 2026-10-27). Chromatic's `disableSnapshot` skips its visual test rather than promising to keep a separate check ([Chromatic parameters](https://docs.chromatic.com/docs/params/), read 2026-10-27). Lost Pixel accepts a directory of screenshots produced by Playwright as custom shots, so its image selection cannot define whether the originating Playwright assertions ran ([Lost Pixel README](https://github.com/lost-pixel/lost-pixel/blob/main/README.md), read 2026-10-27; the repository was archived in April 2026). Argos uploads screenshots from a test runner; its screenshot tags filter *review*, not the originating test's assertions ([Argos tag-filter changelog](https://argos-ci.com/changelog/2026-03-30-screenshot-filters), read 2026-10-27). These tools do not share one filter contract. Shotwright's own `--only` contract is specifically write selection, making the current skip a bug.

**Verdict — ship.** After run-dir and name validation, await `opts.check` before `shouldCapture`; a rejection fails the Playwright test, and no PNG or sidecar is written for a filtered shot. For a captured shot, preserve `checked` as callback completion only; `checked` stays absent when nothing is written (`src/capture.ts:200-214`, `src/manifest.ts:14-28`). A check may read an earlier shot's file: if `--only` filtered out that earlier capture, this check will now fail because its input was never written. This is a prior-shot dependency, since a check already runs before its own capture (`src/capture.ts:165-174`). Document that checks must not depend on filtered capture output; they may have other side effects and still run under `--only`. P must add a regression test with an earlier filtered shot and a later check that reads its file, alongside passing and failing filtered checks, no screenshot call, no sidecar, and the ordinary captured path. A failed check should fail the test even if no shot was selected; otherwise the flag changes verification while claiming to change only output.

## C3 — artifact path and scratch space

**Code and ask.** `artifact()` returns `Promise<void>` (`src/capture.ts:239-242`), copies into `data/<spec>/<name>` (`src/capture.ts:250-253`), and records byte count after the write (`src/capture.ts:274-289`). The factory points Playwright's `outputDir` at `<run>/.pw` (`src/index.ts:102-105`); the reporter removes that directory in `onExit`, regardless of pass/fail (`src/reporter.ts:210-219`). The consumer wants the destination path or a scratch directory to inspect a generated file with another tool.

**Prior art and alternatives.** Playwright's `testInfo.outputPath()` returns a unique path within the per-test output directory, and `testInfo.outputDir` is absolute; `testInfo.attach({path})` copies the file for reporters, so the source may be removed afterward ([TestInfo](https://playwright.dev/docs/api/class-testinfo), read 2026-10-27). Its `Download.saveAs()` also copies to a caller-chosen path and returns `Promise<void>` ([Download](https://playwright.dev/docs/api/class-download), read 2026-10-27). Conversely `page.screenshot()` returns a Buffer even if a path is supplied, a useful capture result rather than a location promise ([Page](https://playwright.dev/docs/api/class-page), read 2026-10-27). The comparable APIs distinguish temporary source paths from published attachments.

**Local experiment.** A browserless test wrote via `test.info().outputPath('scratch.txt')`, then deliberately failed. A run assembled its failed manifest and copied failure context; afterward no `.pw` directory remained. This confirms cleanup also occurs on normal failed-run reporter exit. It does not establish cleanup after a hard process kill. The probe directory and run were removed.

**Verdict — ship differently.** Document `test.info().outputPath('file.pdf')` as the per-test scratch path: generate there, inspect there, then publish via `artifact({path, contentType})` when desired (`src/capture.ts:239-289`). This covers the reported PDF/workbook inspection case while keeping the `void` return. The source path remains available to the caller, so withholding the published destination is not a meaningful mutation guard. Shotwright's reporter removes the `.pw` scratch directory at ordinary pass or fail exit (`src/reporter.ts:210-219`); inspect and publish before the test completes. Hard process termination does not promise this cleanup. A new `scratchDir()` duplicates Playwright's API without addressing a missing capability. Revisit a destination-path return only for a concrete case the source-path workflow cannot serve.

## C4 — copying large artifacts

**Code and ask.** The path branch calls `fs.readFileSync(opts.path)` and writes the whole resulting Buffer through the exclusive fd (`src/capture.ts:254-279`); sidecar bytes use Buffer length (`src/capture.ts:280-289`). The consumer proposes streaming or moving a source file, including a Playwright download.

**Prior art and alternatives.** Playwright `testInfo.attach({path})` copies into reporter-accessible storage, then allows the original to be removed ([TestInfo](https://playwright.dev/docs/api/class-testinfo), read 2026-10-27). `Download.saveAs()` likewise copies and returns no destination path ([Download](https://playwright.dev/docs/api/class-download), read 2026-10-27). Node's file streams can write through a supplied file descriptor; a stream avoids loading an entire input into one Buffer ([Node file system streams](https://nodejs.org/api/fs.html#fscreatewritestreampath-options), read 2026-10-27). A move would transfer source ownership, potentially across filesystems, and alter retry/cleanup semantics; neither comparable API requires it.

**Verdict — ship.** Stream the path source into the fd from `openWrite`, retaining `O_EXCL`/`O_NOFOLLOW` (`src/capture.ts:89-97`) and parent validation (`src/capture.ts:71-86`). Count transferred bytes, close descriptors once, remove an incomplete destination only if it is still the claimed inode, and write the sidecar only after successful copy. Keep `body` Buffer/string semantics. Defer move until a measured copying bottleneck remains: it would need an ownership contract, cross-device fallback, and safe replacement policy. The streaming change is bounded-memory with respect to file size but is not an atomic whole-file publish; readers should rely on the sidecar/manifest boundary.

## C5 — Node engines and ESM

**Code and ask.** The package is ESM, advertises Node `>=20`, exports `types` and `default` without `require`, and checks distribution using publint plus attw's ESM-only profile (`package.json:5`, `package.json:12-14`, `package.json:24-37`, `package.json:41-45`). The README distinguishes the unflagged CommonJS floor (`README.md:31-35`). The consumer asks for engines matching that floor or a `require` condition. E11 previously declined narrowing solely for CommonJS compatibility (`docs/shotwright-746.32-research.md`, D3).

**Prior art and alternatives.** Node documents unflagged `require(esm)` from 20.19.0 and 22.12.0, only for a synchronous ESM graph; an export condition pointing to the same ESM file cannot make older Node load it ([Node CommonJS modules](https://nodejs.org/api/modules.html#loading-ecmascript-modules-using-require), read 2026-10-27). Node 20 reached end of life on **2026-04-30**; 22 is supported to 2027-04-30 and 24 to 2028-04-30 ([Node release schedule data](https://github.com/nodejs/Release/blob/main/schedule.json), read 2026-10-27). Node's releases page lists 22 and 24 as LTS and 26 as Current ([Node releases](https://nodejs.org/en/about/previous-releases), read 2026-10-27); its "Mar 24, 2026" for v20 is a last-updated date, not the EOL date. Playwright's current installation docs recommend current 22, 24, or 26. Sindre Sorhus's ESM migration precedent used `type: module`, exports, and an engine floor rather than a parallel CJS build ([ESM move](https://github.com/sindresorhus/meta/discussions/15), read 2026-10-27). ATTW calls CJS resolving to ESM a compatibility issue for old CJS resolution ([ATTW discussion](https://github.com/arethetypeswrong/arethetypeswrong.github.io/issues/198), read 2026-10-27); shotwright already checks against an ESM-only profile (`package.json:44`).

Comparable package metadata shows no single Node-engine convention (each upstream manifest read 2026-10-27):

| Package | `engines.node` |
| --- | --- |
| [@playwright/test](https://github.com/microsoft/playwright/blob/main/packages/playwright-test/package.json) | `>=20` |
| [Vite](https://github.com/vitejs/vite/blob/main/packages/vite/package.json) | `^20.19.0 \|\| >=22.12.0` |
| [Vitest](https://github.com/vitest-dev/vitest/blob/main/packages/vitest/package.json) | `^22.12.0 \|\| ^24.0.0 \|\| >=26.0.0` |
| [ESLint](https://github.com/eslint/eslint/blob/main/package.json) | `^20.19.0 \|\| ^22.13.0 \|\| >=24` |

**Verdict — ship differently. Decided by owner 2026-10-27:** Set `engines.node` to `>=22.12.0` for 0.4.0 and update install guidance to the same floor. This is a runtime-support policy choice independent of CommonJS convenience: Node 20 is EOL, and 22.12 is the first maintained-major version with unflagged synchronous `require(esm)`. It deliberately drops Node 20 ESM import consumers and Node 22.0–22.11, so release notes must say so. The open-ended `>=` also admits odd-numbered majors. That is accepted because those Current lines are short-lived, and Vite and Playwright also admit them through open-ended ranges in their manifests above. Keep one ESM build and existing exports; a `require` condition to the same ESM would be misleading, and a CJS build adds distribution and dual-package complexity without a stated consumer requirement. `require(esm)` can still fail for a future top-level-await graph; document that qualification.

## C6 — per-shot note

**Code and ask.** `ShotOptions` has `check` and screenshot controls but no note (`src/capture.ts:27-37`). The sidecar writes name, spec, linkage, and checked state (`src/capture.ts:200-214`); `ShotEntry` has no note (`src/manifest.ts:14-28`). Gallery cards search name/spec/test title and render an escaped title path (`src/gallery/render.ts:110-120`, `src/gallery/render.ts:147-152`). The consumer wants a note for a row within one test.

**Prior art and alternatives.** Playwright annotations carry a type and description at the test level, useful for report context but too coarse for several shots in one test ([Playwright annotations](https://playwright.dev/docs/test-annotations), read 2026-10-27). Argos attaches test title/location plus snapshot tags and lets reviewers filter individual screenshots by tags ([Argos Diff](https://argos-ci.com/diff), [Argos tags](https://argos-ci.com/changelog/2026-03-30-screenshot-filters), read 2026-10-27). Chromatic associates each snapshot with a test and allows custom snapshot names; it uses per-test parameters such as `disableSnapshot`, rather than a separate free-text note in the cited APIs ([Chromatic snapshots](https://docs.chromatic.com/docs/snapshots/), [parameters](https://docs.chromatic.com/docs/params/), read 2026-10-27). Percy identifies a snapshot by name and supports per-snapshot browser settings ([Percy snapshot configuration](https://www.browserstack.com/docs/percy/references/browser-config-snapshot-level), read 2026-10-27). Lost Pixel's page shots have a `name`, and its custom-shots mode imports screenshot files; its archived docs show no comparable note contract ([Lost Pixel README](https://github.com/lost-pixel/lost-pixel/blob/main/README.md), read 2026-10-27). These precedents favor stable identity in the name/test and optional context beside it.

**Verdict — ship.** Add optional `note?: string` to `shot()` and the v2 shot sidecar/entry; display it escaped on the gallery card and include it in search. Keep `(spec,name)` identity, file path, duplicate detection, and compare pairing unchanged ([ADR 0021](adr/0021-shot-identity-and-manifest-v2.md)). **Backward compatibility:** a new reader accepts old v2 entries with no `note`; validate a present note as a string. **Forward compatibility:** the current old reader rebuilds shot entries from a fixed field list and drops `note` (`src/gallery/model.ts:112-133`), but still opens the run and pairs shots by `(spec,name)` (`src/gallery/compare-model.ts:221-230`). Viewing or searching notes requires the new reader. This is metadata loss, not run breakage, so no manifest-version bump is needed. P must add mixed-version reader fixtures covering an old reader opening a noted run and a new reader opening an unnoted run. The note is run-local descriptive text and may differ across two runs without creating a new pair. Avoid unbounded card layout and hidden data: P should pin a reasonable rendered length or wrapping rule, plus escaping and search behavior. A note is useful here because test title paths already shipped yet one test may capture several rows (`src/gallery/render.ts:119-120`).

## Proposed implementation waves and the 0.4.0 boundary

| Wave | Items | Write surface | Release impact |
| --- | --- | --- | --- |
| Selection and checks | C1, C2 | `src/index.ts`, `src/capture.ts`, config/capture tests, README and template guidance | Include in the chosen 0.4.0 boundary. Upgrade notes: move top-level viewport/scale into each `project.use` when supplying `projects`; make checks independent of capture files excluded by `--only`. |
| Artifact handling | C3, C4 | `src/capture.ts`, reporter contract tests, README; no new scratch API | Include in 0.4.0 if bundled; C4 alone is an internal improvement and C3 documentation alone does not change behavior. |
| Distribution | C5 | `package.json`, README, release notes, supported-runtime smoke | Include in 0.4.0. Upgrade notes: Node 20 and Node 22.0–22.11 consumers must move to Node 22.12+ or another admitted runtime. |
| Metadata and gallery | C6 | `src/capture.ts`, `src/manifest.ts`, `src/gallery/model.ts`, `src/gallery/render.ts`, tests, README | Include in 0.4.0. The optional v2 field needs no manifest version bump; the gallery change must be viewed before shipping. |

The waves describe independent write surfaces where possible; capture is shared between C2, C4, and C6, so they need one owner or sequential integration. The project chooses one consolidated 0.4.0 as its compatibility boundary. SemVer permits API changes while the major version is zero ([SemVer specification](https://semver.org/), read 2026-10-27); it does not require a 0.4.0 release for these changes. In npm's caret semantics, a consumer on `^0.3.0` will not receive 0.4.0 without changing its range ([node-semver range documentation](https://github.com/npm/node-semver#caret-ranges-123-025-004), read 2026-10-27). The decisions above do not reverse ADR 0021 or ADR 0024; C5 changes the earlier E11 runtime recommendation because Node 20 is now EOL, and its support policy should be stated in release notes.
